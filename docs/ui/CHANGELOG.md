# Changelog

## UI engine 0.2.0 (glocon 0.7.0 candidate)

Complete collection and reviewed destinations are part of the report/check contract. Reports can include explicit passing, failing and manual-review coverage outcomes; a rule listed as executed alone does not establish baseline resolution. Public report/contract options and failure thresholds validate JavaScript inputs. UTF-16 fingerprint hashing preserves ASCII/BMP identities and corrects supplementary-Unicode targets.

Browser collection handles inherited ignore declarations, visibility overrides and `display: contents` labels. Page audits and CLI scans have shared total deadlines. Project runs use bounded concurrency, progress callbacks and an exclusive artifact lock. CI report uploads are opt-in, with separate screenshot opt-in and retention limits.

See the [current integration contract](integrations.md), [project workflow](project-checks.md) and [independent-trial protocol](../readiness-trials.md). These changes do not claim broader platform certification or completed independent usability trials.

## UI engine 0.1.0 (included in glocon 0.3.0)

First release: a framework-independent UI/UX audit engine, rendered browser checks with axe, state contracts, a CLI with JSON output, React form/state primitives, shared CSS tokens, and a supplied-node native adapter.

Includes documented confidence and coverage limits, configurable severity and suppressions, ESM/CommonJS exports, TypeScript declarations, research rationale, and automated tests.
